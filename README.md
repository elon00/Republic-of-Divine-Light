# 🏛️ Republic of Divine Light (RDL)

## Unified RDL Repository Architecture

The Republic of Divine Light (RDL) project is being consolidated around one canonical implementation repository:

**Canonical implementation:** `elon00/pq-rdl-blockchain`

This repository is retained as the public identity and ecosystem landing repository. The canonical repository contains the current runnable prototype, Conway automaton modules, PQC research interfaces, AI copilot endpoint, and demonstration chain state.

## Current reality status

The current RDL implementation is a **research and prototype system**.

It must not be represented as evidence of:

- a live distributed blockchain or validator network,
- real TPS, hashrate, or active-node telemetry,
- deployed smart contracts on Solana or another public blockchain,
- production-grade post-quantum cryptographic certification,
- independently audited security, legal compliance, or autonomous government.

Local blocks, transactions, contracts, rewards, and chain state are currently **in-memory demonstrations** unless independent deployment evidence is published.

## Governance principles

1. **Truth over presentation** — demonstrations must be labelled as demonstrations.
2. **Evidence before verification claims** — deployment, cryptography, audits, and compliance require reproducible evidence.
3. **Human accountability** — AI-generated recommendations are not sovereign legal or security authority.
4. **Security by default** — secrets remain server-side and are never committed.
5. **Open reproducibility** — meaningful claims should be testable from documented code and commands.

## Canonical workflow

```text
Research → Prototype → Tests → Evidence → Independent Review → Deployment → Verified Status
```

Until the evidence stage is complete, the correct status is **PROTOTYPE / UNVERIFIED**, not production.
